# OCPP 2.0.1 Implementation Design

**Date:** 2026-04-07
**Status:** Approved

## Overview

Add comprehensive OCPP 2.0.1 support to the ChargeGhost EVSE Simulation Engine. The implementation uses a config-driven protocol switch (`ocpp_version: "2.0.1"`) — a single station instance speaks one protocol version at a time. The existing engine remains protocol-agnostic; only the OCPP adapter layer changes.

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Scope | Comprehensive (all 2.0.1 features except ISO 15118 certs) | Full CSMS testing coverage |
| Protocol switching | Config flag, one version per instance | Mirrors real hardware behavior |
| Package structure | Interface-first (`OCPPBridge` interface, `v16/` and `v201/` packages) | Clean separation, battle-tested interface |
| OCPP library | Continue with `lorenzodonini/ocpp-go` | Already supports 2.0.1, single dependency |
| Device model scope | Minimal viable (~25 variables) | Lean start, easy to extend |
| ISO 15118 certs | Excluded | Niche, complex PKI, not needed for simulator |
| Testing | Unit + integration suite with mock CSMS | End-to-end confidence |
| Implementation order | Refactor-then-build with vertical slices | De-risks interface extraction before 2.0.1 work |

## Shared OCPPBridge Interface

```go
package ocpp

type OCPPBridge interface {
    Start(ctx context.Context) error
    Stop()
    IsConnected() bool
    GetHeartbeatInterval() int

    // Outbound messages (version-agnostic names)
    SendBootNotification() error
    SendHeartbeat() error
    SendStatusNotification(connectorID int, errorCode, status string) error
    SendMeterValues(connectorID int, value float64, transactionID int, context string) error
    SendAuthorize(idTag string) error

    // Transaction lifecycle
    // Returns transaction ID: server-assigned int for 1.6, locally-generated for 2.0.1.
    // The int return is used by the engine for transaction tracking; v201 assigns a
    // synthetic incrementing int internally (the actual UUID is managed by the builder).
    SendTransactionStart(connectorID int, idTag string, meterStart float64, timestamp time.Time, reservationID *int) (int, error)
    SendTransactionStop(meterStop float64, timestamp time.Time, transactionID int, reason string, meterHistory []engine.MeterRecord) error

    // Firmware/Diagnostics
    SendFirmwareStatusNotification(status string) error
    SendDiagnosticsStatusNotification(status string) error

    // Data transfer
    SendDataTransfer(vendorID, messageID, data string) (string, string, error)
}
```

**Factory function:**

```go
func NewBridge(version string, e *engine.Engine, hub *wsapi.Hub, cfg *config.Config,
    dispatcher *CommandDispatcher, /* ...shared managers... */) (OCPPBridge, error) {
    switch version {
    case "1.6":
        return v16.NewBridge(e, hub, cfg, dispatcher, ...)
    case "2.0.1":
        return v201.NewBridge(e, hub, cfg, dispatcher, ...)
    default:
        return nil, fmt.Errorf("unsupported OCPP version: %s", version)
    }
}
```

## OCPP 2.0.1 Message Coverage

### Provisioning
- `BootNotification` — sends `ChargingStation` model (vendor, model, serial, firmware version)
- `Heartbeat` — unchanged semantically

### Authorization
- `Authorize` — uses `IdToken` (idToken string + type enum: ISO14443, eMAID, Central, Local, etc.)
- `GroupIdToken` support for fleet authorization
- `SendLocalList` / `GetLocalListVersion` — new message format, same concept

### Transactions (replaces Start/Stop/MeterValues)

Single `TransactionEvent` message with three event types:

| eventType | triggerReason examples | replaces |
|-----------|----------------------|----------|
| Started | Authorized, CablePluggedIn, RemoteStart | StartTransaction |
| Updated | MeterValuePeriodic, ChargingStateChanged | MeterValues |
| Ended | StopAuthorized, RemoteStop, DeAuthorized, EnergyLimitReached | StopTransaction |

Key differences from 1.6:
- Station generates `transactionId` (string/UUID), no server-assigned ID
- `seqNo` increments per event within a transaction
- Meter values embedded in TransactionEvent, not separate messages
- `chargingState` field: Charging, SuspendedEV, SuspendedEVSE, Idle

**TransactionEventBuilder** — one per active session, keyed by EVSE ID:

```go
type TransactionEventBuilder struct {
    transactionID string  // UUID, generated at session start
    seqNo         int     // increments per event
    evseID        int
    connectorID   int
    LastCost      *float64 // updated by CostUpdated
}

func (b *TransactionEventBuilder) Started(idToken IdToken, meterValue *MeterValue) *TransactionEventRequest
func (b *TransactionEventBuilder) Updated(trigger TriggerReason, meterValue *MeterValue) *TransactionEventRequest
func (b *TransactionEventBuilder) Ended(reason StopReason, meterValue *MeterValue) *TransactionEventRequest
```

Engine callback mapping:
| Engine Callback | 2.0.1 Action |
|---|---|
| `OnSessionStarted` | `TransactionEvent(Started)` |
| Meter tick | `TransactionEvent(Updated, MeterValuePeriodic)` |
| `OnSessionStopped` | `TransactionEvent(Ended)` |
| Plug in (no auth) | `TransactionEvent(Started, CablePluggedIn)` with chargingState=Idle |

Remote operations:
- `RequestStartTransaction` — includes evseId, idToken, groupIdToken, optional chargingProfile → `engine.StartSession()`
- `RequestStopTransaction` — takes transactionId (string) → bridge looks up EVSE → `engine.StopSession()`

### Device Model

Replaces 1.6's flat configuration keys with Component → Variable → VariableAttribute hierarchy.

**Minimal variable set (~25 variables):**

```
ChargingStation
  ├── AvailabilityState       (dynamic, read-only)
  ├── Model                   (static, read-only, from config)
  ├── VendorName              (static, read-only, from config)
  ├── FirmwareVersion         (static, read-only, updatable via firmware)
  ├── SerialNumber            (static, read-only)
  └── SupplyPhases            (static, read-only)

EVSE (per EVSE)
  ├── AvailabilityState       (dynamic, read-only)
  ├── Power                   (dynamic, read-only)
  └── SupplyPhases            (static, read-only)

Connector (per Connector)
  ├── AvailabilityState       (dynamic, read-only)
  ├── ConnectorType           (static, read-only, from config)
  └── SupplyPhases            (static, read-only)

SampledDataCtrlr
  ├── TxUpdatedInterval       (read-write, replaces MeterValueSampleInterval)
  └── TxUpdatedMeasurands     (read-write, replaces MeterValuesSampledData)

OCPPCommCtrlr
  ├── HeartbeatInterval       (read-write)
  ├── WebSocketPingInterval   (read-write)
  └── RetryBackOffRepeatTimes (read-write)

AuthCtrlr
  ├── Enabled                 (read-write)
  ├── LocalAuthorizeOffline   (read-write)
  └── AuthorizeRemoteStart    (read-write)

TxCtrlr
  ├── StopTxOnInvalidId       (read-write)
  └── StopTxOnEVSideDisconnect (read-write)
```

**Implementation:**

```go
type DeviceModel struct {
    mu        sync.RWMutex
    variables map[ComponentVariable]VariableAttribute
    engine    EngineView
}

type ComponentVariable struct {
    Component string // "EVSE", "Connector", "ChargingStation", etc.
    Instance  string // "1", "2" (for per-EVSE/connector)
    Variable  string // "AvailabilityState", "Power", etc.
}

type VariableAttribute struct {
    Value      string
    Mutability string // ReadOnly, ReadWrite, WriteOnly
    Persistent bool
    Constant   bool
}
```

Behaviors:
- Static variables populated from config at startup (read-only)
- Dynamic variables (AvailabilityState, Power) delegate to engine via EngineView on read
- Writable variables update both the store and the corresponding runtime behavior
- `GetBaseReport` iterates all variables → sends `NotifyReport` messages
- `GetReport` filters by component criteria

Messages: `SetVariables`, `GetVariables`, `GetBaseReport`, `GetReport`, `NotifyReport`

### Availability
- `StatusNotification` — per-EVSE and per-Connector, uses `ConnectorStatus` enum (Available, Occupied, Reserved, Unavailable, Faulted)
- `ChangeAvailability` — targets station (evseId=0), EVSE, or connector

### Smart Charging
- `SetChargingProfile` / `ClearChargingProfile` — EVSE-level targeting
- `GetCompositeSchedule` — reuses existing algorithm, new response format
- `GetChargingProfiles` / `ReportChargingProfiles` — station pushes profiles to CSMS
- `NotifyEVChargingSchedule` / `NotifyEVChargingNeeds` — stub responses (EV-side reporting)

### Variable Monitoring
- `SetVariableMonitoring` — register UpperThreshold, LowerThreshold, Delta, or Periodic monitors on device model variables
- `ClearVariableMonitoring` — remove by monitor ID
- `GetMonitoringReport` / `NotifyMonitoringReport` — query/report active monitors
- `NotifyEvent` — fires when monitor condition is met

**MonitoringManager:**

```go
type MonitoringManager struct {
    mu       sync.RWMutex
    monitors map[int]Monitor
    nextID   int
    model    *DeviceModel
    bridge   OCPPBridge
}

type Monitor struct {
    ID           int
    ComponentVar ComponentVariable
    Type         MonitorType  // UpperThreshold, LowerThreshold, Delta, Periodic
    Value        float64
    Severity     int          // 0-9
    LastValue    *float64
    LastCheck    time.Time
}
```

Evaluation: goroutine ticking ~1s, reads current values from device model, fires `NotifyEvent` when conditions are met. Numeric variables support all monitor types; string variables support Delta only (value changed).

### Display Messages
- `SetDisplayMessage` / `GetDisplayMessage` / `ClearDisplayMessage` / `NotifyDisplayMessages`
- In-memory `DisplayMessageStore` with CRUD
- Broadcasts changes over WebSocket for UI rendering

### Cost Updates
- `CostUpdated` — CSMS pushes `totalCost` + `transactionId`
- Stored on TransactionEventBuilder, broadcast via WebSocket

### Firmware
- `UpdateFirmware` — reuses `FirmwareManager` interface, adds `retries`/`retryInterval` fields
- `FirmwareStatusNotification` — same state machine
- `PublishFirmware` / `UnpublishFirmware` — stub responses (Accepted/no-op)

### Remote Operations
- `TriggerMessage` — extended trigger list (adds TransactionEvent, LogStatusNotification)
- `Reset` — adds `OnIdle` type: if transactions active, store pending flag, execute when last transaction ends
- `UnlockConnector` — targets by evseId + connectorId
- `DataTransfer` — unchanged, reuses shared DataTransferRegistry

### Excluded
- ISO 15118 certificate management (Get15118EVCertificate, CertificateSigned, InstallCertificate, DeleteCertificate, GetInstalledCertificateIds)

## Config Changes

One new field in `Config`:

```go
ConnectorType string `json:"connector_type"` // e.g. "cType2", "cCCS2" — used by v201 device model
```

Existing `OCPPVersion` field gains `"2.0.1"` as valid value (already defaults to `"1.6"`).

## main.go Wiring

```go
// Factory returns OCPPBridge interface
bridge, err := ocpp.NewBridge(cfg.OCPPVersion, e, hub, cfg, dispatcher, ...)
if err != nil {
    slog.Error("unsupported OCPP version", "version", cfg.OCPPVersion)
    os.Exit(1)
}
bridge.Start(ctx)
```

For `"2.0.1"`: DeviceModel, MonitoringManager, DisplayMessageStore constructed instead of ConfigKeyManager.
Shared infra (CommandDispatcher, MessageQueue, AuthorizationCache, FirmwareManager, DiagnosticsManager, DataTransferRegistry) passed to either bridge.

REST API impact: only `POST /api/v1/ocpp/send` needs version routing for DataTransfer.

## Testing Strategy

### Unit Tests (per package)
- `v201/bridge_test.go` — construction, connection lifecycle, heartbeat
- `v201/transaction_test.go` — TransactionEventBuilder: Started/Updated/Ended, seqNo, triggerReasons, meterValue embedding
- `v201/device_model_test.go` — Get/SetVariables, mutability enforcement, GetBaseReport
- `v201/monitoring_test.go` — monitor registration, threshold/delta/periodic triggering, clear
- `v201/display_test.go` — DisplayMessageStore CRUD, priority filtering
- `v201/cost_test.go` — CostUpdated storage and WebSocket broadcast
- `v201/handlers_test.go` — each inbound handler returns correct responses
- `v16/*_test.go` — existing tests moved with code, must pass after restructure
- `ocpp/bridge_test.go` — factory returns correct implementation

### Integration Tests (`v201/integration_test.go`)
Uses `ocpp-go`'s `ocpp2.NewCSMS()` as in-process mock CSMS on localhost:

1. **TestFullChargingFlow** — boot → status → plug → authorize → TransactionEvent(Started) → TransactionEvent(Updated) → TransactionEvent(Ended) → unplug
2. **TestRemoteStartStop** — CSMS sends RequestStartTransaction → engine starts → CSMS sends RequestStopTransaction → engine stops → verify TransactionEvent sequence
3. **TestDeviceModelRoundTrip** — GetVariables returns correct values, SetVariables updates writables / rejects read-only, GetBaseReport triggers NotifyReport
4. **TestOfflineQueueDrain** — disconnect, charge, reconnect → queued TransactionEvents drain in order

## Implementation Phases

### Phase 1 — Refactor (no new functionality)
1. Extract `OCPPBridge` interface in `internal/ocpp/bridge.go`
2. Move 1.6J code into `internal/ocpp/v16/`
3. Add factory function
4. Update `main.go` imports and wiring
5. Full test pass — no behavioral changes

### Phase 2 — Minimal 2.0.1 vertical slice
1. Scaffold `v201/bridge.go` — CSMS connection, BootNotification, Heartbeat
2. StatusNotification (2.0.1 format)
3. Wire into `main.go` behind `OCPPVersion: "2.0.1"`
4. Integration test: boot → heartbeat → status roundtrip

### Phase 3 — Transaction lifecycle
1. TransactionEventBuilder
2. Started/Updated/Ended mapped to engine callbacks
3. Authorize with IdToken model
4. RequestStartTransaction / RequestStopTransaction handlers
5. Offline queue integration
6. Integration test: full charge flow

### Phase 4 — Device Model
1. DeviceModel struct with minimal variable set
2. GetVariables / SetVariables handlers
3. GetBaseReport / NotifyReport
4. Integration test: CSMS reads/writes variables

### Phase 5 — Smart Charging (2.0.1 format)
1. SetChargingProfile / ClearChargingProfile (EVSE targeting)
2. GetCompositeSchedule (reuse algorithm, new response format)
3. GetChargingProfiles / ReportChargingProfiles

### Phase 6 — Monitoring, Display, Cost

### Phase 7 — Remaining operations

### Phase 8 — Polish
