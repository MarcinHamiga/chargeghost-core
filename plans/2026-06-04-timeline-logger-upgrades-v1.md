# Plan 7: Timeline Logger Upgrades (C1, C2, C5)

**Date:** 2026-06-04
**Version:** v1
**Source review:** 2026-06-04 OCPP communications review, recommendations C1, C2, C5
**Priority:** P2 — observability

## Objective

Add correlation IDs to the timeline, include the request payload in
`LogError`, and record response timing.

## Background

`internal/ocpp/timeline_logger.go` records inbound and outbound messages with
direction, ID, and payload summary. But:

- There's no shared ID linking an inbound CSMS call to the engine callback to
  the outbound response.
- `LogError(action, direction, connectorID, errMsg)` discards the request
  payload — only the error string is logged.
- The timeline doesn't measure how long the CSMS took to respond.

## Design

### 1. Correlation IDs

Generate a UUID per inbound CSMS call. Propagate through:

- The handler (`b.tl.LogInbound(...)` already takes a correlationID param —
  verify usage)
- The engine callback (new field on callbacks or a `context.Context`)
- The response log

If ocpp-go v0.19.0 doesn't propagate message IDs through to handlers, fall
back to a per-handler call counter.

### 2. Request payload in LogError

Add a `LogError` variant that includes payload:

```go
func (tl *TimelineLogger) LogErrorWithPayload(action string, direction Direction,
    connectorID *int, correlationID string, err error, payload string) {
    // existing LogError + write payload to log + to a "errors" timeline file
}
```

Call sites: dispatcher Run, v2.0.1 senders, v1.6 senders.

### 3. Response timing

Add `tl.LogTiming(action, correlationID, start time.Time)` called from
senders after a send completes. Records `time.Since(start)` in the timeline.
